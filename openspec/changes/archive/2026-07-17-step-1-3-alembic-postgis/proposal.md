## Why

Step 1.1–1.2 established SQLAlchemy `Base`, mixins, and async session plumbing, but the database has no migration toolchain yet. Step **1.3** (`docs/steps/step1.md`) adds Alembic with async support and migration 001 to enable PostGIS and `uuid-ossp` — prerequisites for geometry columns in Place models (1.4b) and UUID defaults in seed scripts.

## What Changes

- Add `alembic==1.18.4` and `geoalchemy2==0.20.0` to `requirements.txt` (with step comments per AGENT.md).
- Replace placeholder `alembic.ini` with real config: `script_location`, UTC timezone, date-prefixed revision filenames; **no** hardcoded `sqlalchemy.url`.
- Replace placeholder `alembic/env.py` with async Alembic env: inject `DATABASE_URL` from `get_settings()`, wire `Base.metadata`, import `geoalchemy2` for autogenerate, empty model-import block until 1.4a.
- Create manual migration `alembic/versions/001_enable_postgis.py`: `CREATE EXTENSION` for `postgis`, `postgis_topology`, and `uuid-ossp`; downgrade is no-op (extensions not dropped).
- Validate with `alembic upgrade head` against local Docker Postgres (`postgis/postgis:16-3.4` on port 5433).

### Non-goals

- No SQLAlchemy domain models (step 1.4a–1.4d).
- No `alembic upgrade` in app startup — deploy/CLI only.
- No autogenerated migration 002 yet (comes after models land).
- No changes to `session.py`, routers, or auth.
