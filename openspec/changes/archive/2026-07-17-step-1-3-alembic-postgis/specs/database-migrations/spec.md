## ADDED Requirements

### Requirement: Alembic uses runtime database URL from settings

The migration toolchain MUST read `DATABASE_URL` from `get_settings()` at runtime. The value MUST NOT be hardcoded in `alembic.ini`.

#### Scenario: Env injection on migration run

- **WHEN** an operator runs `alembic upgrade head` with a valid `.env` / environment
- **THEN** Alembic connects using the same async URL as the application (`postgresql+asyncpg://…`)

### Requirement: Alembic supports async SQLAlchemy migrations

The Alembic environment MUST use `async_engine_from_config` with `NullPool` and `connection.run_sync()` so migrations work with the project's async SQLAlchemy stack.

#### Scenario: Online async migration execution

- **WHEN** `alembic upgrade head` runs in online mode (default)
- **THEN** migrations execute via an async engine without blocking the event loop incorrectly and the engine is disposed after completion

### Requirement: geoalchemy2 is registered for autogenerate

`alembic/env.py` MUST import `geoalchemy2` (side-effect registration) so future autogenerated migrations emit correct PostGIS geometry types instead of VARCHAR/Text.

#### Scenario: Geometry type registration

- **WHEN** a developer later adds a model with a `Geometry` column and runs autogenerate
- **THEN** the generated migration references PostGIS geometry types (not plain string columns)

### Requirement: Migration 001 enables PostGIS extensions

Migration revision `001` MUST create PostgreSQL extensions `postgis`, `postgis_topology`, and `uuid-ossp` using `CREATE EXTENSION IF NOT EXISTS`.

#### Scenario: Fresh database upgrade

- **WHEN** `alembic upgrade head` runs against an empty `wandr` database on the PostGIS Docker image
- **THEN** output includes `Running upgrade  -> 001` and all three extensions appear in `\dx`

#### Scenario: Idempotent extension creation

- **WHEN** migration 001 runs on a database where extensions already exist
- **THEN** the upgrade completes without error

### Requirement: Migration downgrade does not drop extensions

Migration 001 downgrade MUST be a no-op. Shared PostgreSQL extensions MUST NOT be dropped on rollback.

#### Scenario: Downgrade safety

- **WHEN** `alembic downgrade base` runs after upgrade
- **THEN** `postgis`, `postgis_topology`, and `uuid-ossp` remain installed

### Requirement: Migrations are not invoked at application startup

The FastAPI application MUST NOT call `alembic upgrade` during lifespan or startup. Migrations are a deploy/CLI concern only.

#### Scenario: App startup without migration side effects

- **WHEN** `uvicorn src.main:app` starts
- **THEN** no Alembic migration commands run automatically

### Requirement: Model imports block starts empty

`alembic/env.py` MUST include a documented model-import section that is empty until step 1.4a. Each new `models.py` MUST be imported there before autogenerate can detect it.

#### Scenario: Autogenerate with no models

- **WHEN** autogenerate runs before domain models exist
- **THEN** no table-creation operations are emitted (only extension migration 001 is pending)
